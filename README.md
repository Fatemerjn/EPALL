# Privacy-Aware Lifelong Learning

This repository contains the task-wise continual learning and unlearning code used for PALL-style experiments, plus the `pall_adapter` prototype on the current `feature/adapter-forgetting` branch.

Paper:
"Privacy-Aware Lifelong Learning"  
<em>Ozan Özdenizci, Elmar Rueckert, Robert Legenstein</em>  
ICLR 2025  
https://openreview.net/forum?id=UstOpZCESc

## Repository Layout

- `main.py`: experiment entrypoint.
- `methods/`, `models/`: method and model implementations.
- `schedules/`: fixed request schedules for reproducible train/forget sequences.
- `tools/`: batch runners and table-generation scripts.
- `docs/`: experiment notes and adapter prototype notes.
- `results/stable/`: curated thesis-ready stable-branch-style tables and summaries.
- `results/adapter/`: curated adapter prototype tables and summaries.
- `results/aggregates/`: aggregated CSV/Markdown outputs built from run directories.
- `runs/`: raw run artifacts generated by experiments.
- `runs_archive/`: reserved location for archived raw or duplicate runs.

## Implemented Methods

- `sequential`
- `ewc`
- `lwf`
- `er`
- `derpp`
- `lsf`
- `clpu`
- `pall_original`
- `pall_modified`
- `pall_adapter`

Notes:

- `--method pall` is normalized to `pall_modified`.
- `pall_adapter` is a prototype on this branch only.
- The pipeline is task-ID-aware: task IDs are known at training, forgetting, and evaluation time.

## Supported Datasets

- `cifar10`
- `cifar100`
- `tinyimagenet`

Current `cifar100` constraint in code:

- `--class_per_task` must be `5`.
- `--n_tasks` must be in `[1, 20]`.

## Stable Thesis Results

Curated stable tables and summaries are under `results/stable/`. The key stable result groups kept in this branch are:

- CIFAR-10 fixed schedule
- CIFAR-100 fixed schedule
- CIFAR-100 ablation
- CIFAR-100 baselines
- CIFAR-100 all-methods comparison

Exact runner commands for the stable experiment families:

```bash
python3 tools/run_pall_pairwise.py \
  --dataset cifar10 --arch resnet18 --class_per_task 2 --n_tasks 5 --n_forget 3 \
  --seeds 0 --request_schedule_file schedules/cifar10_t5_f3_fixed_seed0.json \
  --protect_ratio 0.2 --lambda_protect 0.1 --retrain_steps 50
```

```bash
python3 tools/run_pall_pairwise.py \
  --dataset cifar100 --arch resnet18 --class_per_task 5 --n_tasks 10 --n_forget 3 \
  --seeds 0 --request_schedule_file schedules/cifar100_t10_f3_seed0.json \
  --protect_ratio 0.2 --lambda_protect 0.1 --retrain_steps 50
```

```bash
python3 tools/run_fixed_schedule_baselines.py \
  --dataset cifar100 --arch resnet18 --class_per_task 5 --n_tasks 10 --n_forget 3 \
  --seeds 0 --request_schedule_file schedules/cifar100_t10_f3_seed0.json
```

```bash
python3 tools/run_pall_ablation.py \
  --dataset cifar100 --arch resnet18 --class_per_task 5 --n_tasks 10 --n_forget 3 \
  --seeds 0
```

Aggregate and format results into `results/aggregates/`:

```bash
python3 tools/aggregate_results.py --root runs --out results/aggregates/results_summary.csv
```


## Adapter Prototype

This branch keeps the stable PALL code and adds:

- `models/adapter_resnet.py`
- `methods/pall_adapter.py`
- adapter CLI knobs in `main.py`
- `docs/adapter_notes.md`

Important limitation:

- `pall_adapter uses adapter reset prototype, not full PALL overlap mask yet.`

Curated adapter outputs are under `results/adapter/`.

Smoke test:

```bash
python3 main.py --dataset cifar10 --class_per_task 2 --n_tasks 5 --n_forget 1 \
  --arch resnet18 --method pall_adapter --n_epochs 1 --seed 0
```

Fixed-schedule adapter run:

```bash
python3 main.py --dataset cifar10 --class_per_task 2 --n_tasks 5 --n_forget 3 \
  --arch resnet18 --method pall_adapter --seed 0 --deterministic \
  --request_schedule_file schedules/cifar10_t5_f3_fixed_seed0.json \
  --adapter_bottleneck 16 --adapter_train_classifier
```

See `docs/adapter_notes.md` for adapter-specific notes and commands.

## Run Artifacts

Run directory pattern:

`runs/<dataset>/T<n_tasks>_F<n_forget>/<method>/seed_<seed>/<timestamp>/`

Key files written per run:

- `config.json`
- `metrics.json`
- `results.pth`
- `summary.txt`
- `report.md`
- `events.log`
- `overlap.csv` when `--dump_overlap` is enabled

`runs/` and `runs_archive/` are intentionally treated as raw artifact locations and should usually stay out of version control.
